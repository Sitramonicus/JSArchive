## 1. What the logs' silence does NOT mean

The big visible differences (missing [O7-DIAG] blocks, fewer Abacus logs, single Satchel line,
no "Cache size") are mostly logging/formatting, not removed features:

- O7.38 prints 6 hard-coded `[O7-DIAG]` blocks (runtime-candidate, export sample, selected runtime,
  scanning count, match primitives, brute-force). O8.1 routes **all** logging through a `Log` module
  (`LOG_LEVEL = 1`, `Log.diag` only prints at level ≥ 2), so its diagnostics are silent by default.
  Its one `Log.diag("Lazy Force", …)` call printed because the banner says "Experimental" —
  i.e. the console snippet you ran was configured with `LOG_LEVEL = 2` (level-2 diagnostics are still
  present but gated, not removed).
- Satchel "Pockets checked" line exists in O8.1 (line 215) and the all-seven gate exists; the extra
  "Cache size: …" text from O7.38/O7.41 was dropped, but both write the identical gate message otherwise.
- Abacus logs: O7.38 prints at `tick % 3 === 1 || GoogleChatter || v.cur >= goal` (GoogleChatter=false).
  O8.1 prints at `tick % 3 === 1 || v.cur >= goal` — same cadence, so both print every ~3 ticks.
- O7.38's export-sample "undefined" came from its `console.debug`-with-second-arg lines
  (`export sample…`, `match primitives`, `Brute-force`); O8.1 removed those three helpers,
  which explains your occasional "undefined" line (that's the DevTools artifact of those two-arg logs).
- Hourglass line: O7.38 condition `firstTick || GoogleChatter` (= first tick only);
  O8.1 condition `tick === 0` (= first tick only) — equivalent, just less noisy.

## 3. Timing / "Poisson"

- `GoogleDelay`: `d*1000 + jitterBuckets[…]` → `d*1000 − ln(1−U)*300` (exponential/Poisson-ish jitter).
- Video step: `4 + floor(rand*8)` → `4 + rand*8` (fractional).
- 429 sleep: `ceil(retryAfter)+1` → `ceil(retryAfter)+1+rand()`; 5xx backoff adds `rand()*2`.

## 4. PID changes (the "Hex"/identity experiments)

- Default PIDs: `(rand*3584 + 512) * 4` (always multiple of 4, i.e. `%4===0` "tiles line up" always true) →
  `rand*60000 + 4096` (arbitrary), plus
- Desktop: fallback `v.pid` → random fallback; **running-game lookup now via dynamic key** `_0x4?.[_0xm1]?.()`
  instead of `.getRunningGames?.()`.
- Stream: previously used `v.pid`; now generates its own random PID.
- Activity stream key: `call:…:1|2|3` → `call:…:<16 hex chars>` ("Hex Keys").
- Game start timestamp: `60–240s` → `120–420s` window.

## 5. Desktop/stream rewrite (new Promise wrapper)

- `_0xplay`/`_0xstream` now `return new Promise((resolve, reject) => { (async () => {…})() })`;
  `cleanup()` resolves the promise; unhandled errors `reject` instead of unhandled; `finishTask()` still
  guarded and `finally { if (!handedOff) finishTask(); }` retained.
- Functionality preserved: hooks, native-code proxies, dispatch, watchdog, subscription cleanup,
  `GoogleProgress` (same logic), activity deadline message, handoff messages.
- Textual: whole blocks got compressed to fewer lines; "hook failed"→"hook"; removed `firstCoin`
  and `_0xdrift` (O7.41 cleanup) and the O7.41 comment line.
