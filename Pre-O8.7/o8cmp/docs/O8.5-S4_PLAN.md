# O.8.5-S4 — Build Plan (2026-09-09)

Scope decisions + roadmap from the seamless/technique/memory/telemetry discussion.

## 0. Locked decisions

1. **Source-first (the long way) for everything structural.** The gist artifact gets
   surgical patches only (password swap already done: `builds/O8.5-current-obf-edit.js`,
   sha `b9e5ff2b...`). Memory layout, decoy-string camo, lexicon mechanics, engine
   choice: all applied on the clean core, then regenerated -> sharded -> obfuscated.
2. **Marker/password scheme:** KEEP 佐藤 結衣 as the searchable marker in the UNOBFUSCATED
   shard/clean line. In the obfuscated result of THAT shard only, 佐藤 結衣 remains
   searchable and replaceable with the canonical phrase (search -> replace -> works).
   The digest stays pinned to the canonical phrase (already true: digest ==
   sha256(salt + canonical), verified). Non-OTO changes applied well before the OTO phase.
3. **Engine:** the USER obfuscates via obfuscator.io (their pipeline), NOT via the
   javascript-obfuscator npm scripts (OTO). OTO scripts still provided as alternates.
   Whole-file uniform seam removal + transport compression run on the USER'S resulting
   artifact (their bundle), after they supply it.
3. **Camo scope:** zero-width (ZWJ/ZWNJ in identifiers, FEFF as inter-token whitespace,
   zw chars inside strings) + RLO in DECOY-ONLY strings, per-instance random via the
   generator's seed RNG. No esoteric full encodings (JSFuck-style expansion blows the
   2-3 MB soft / 5 MB hard paste cap; see below). No fake telemetry.
4. **Memory posture:** encoded-at-rest everywhere (existing band-rot) + per-call
   transient decode + zero retention of decoded tables. No ArrayBuffer "linear heap"
   refactor unless user opts in (item B4).
5. **Engine:** whole-file uniform javascript-obfuscator last-mile pass (verdict from
   seamless trial). Optional js-confuser variant per instance for heterogeneity.
6. **Transport compression** (gzip/deflate/brotli + b64 + ~425 B self-extract shell)
   available at ship time; proven end-to-end.

## 1. Why the "lazy way" (edit the gist artifact) is a dead end for most items

| Change | On obfuscated gist artifact | On clean source -> rebuild |
|---|---|---|
| Password / marker swap | OK (surgical string swap; done) | n/a |
| ZWJ identifier camo | NO (no AST, 1-line, identifier occurrences unsafe to regex) | YES (generator emits; survives rename only as post-pass) |
| RLO/zw inside decoy strings | RISKY (can't tell which strings are inert in obf output) | YES (whitelist known inert decoys) |
| FEFF whitespace sprinkle | MAYBE (token-level insert is safe; but adds to artifact we replace anyway) | YES (post-obf micro-pass) |
| Memory hygiene / pool refactor | NO (structural refactor) | YES |
| Lexicon / phrase rotation | NO | YES |
| Engine rotation | n/a (already obfuscated) | YES |

Rule: anything that touches HOW the code is written goes through the clean line.

## 2. Memory techniques — honest verdicts (vs. the pasted AI pitch)

The pitch's native-level verdicts are right; its three "YES" rows are oversold:
- **ArrayBuffer/typed arrays are NOT invisible.** Chrome heap snapshots list typed
  arrays and their backing stores; DevTools memory inspector reads them; page-level
  JS (or Puppeteer) can read them if it can reach the instance. They change the
  *shape* (one big blob vs. many named strings) but not the *exposure*.
- **"Instantly unreachable ... young-gen sweep" is not a guarantee.** GC timing is
  not script-controllable; a snapshot taken during the decode window still catches
  cleartext. Transient windows only *shrink* exposure.
- **Wasm memory is not an "opaque black box."** DevTools has a wasm memory
  inspector; Puppeteer can read exported memory; heap/linear-memory dumps include it.
  It only moves bytes outside the JS GC heap.
- **The real kernel:** keep sensitive text OUT of V8's *string* heap — encoded at
  rest, decoded near use, never retained. That is already S3's design (band-rot
  lexicon, KC=47/KP=61, decode at log fire). The gap audit (B4) closes the leftovers
  (routes table, phrase literal) without a rewrite.

| Technique | Verdict (revised) |
|---|---|
| TypedArray "linear heap" | PARTIAL — shape change only; heavy refactor; skip unless B4 audit shows a real gap |
| Transient closure isolation | HYGIENE only — shorter windows, no guarantees; already practiced |
| Wasm memory isolation | NO — false black-box claim; cost/complexity not justified for a console paste |

## 3. Whitespace/esoteric languages — rejected on size math

Full JSFuck-style encoding expands source ~7-20x. Our smallest viable product is
~192 KB clean / ~256 KB obfuscated -> JSFuck would land 3-10+ MB: over the 5 MB hard
cap, before adding the shard variety. Whitespace-language-with-interpreter is worse.
Transport compression instead: 192 KB -> ~37 KB paste (brotli-11), 698 KB gist ->
~330 KB, comfortably under the soft limit.

## 4. Roadmap

### Phase A — clean-core changes (o8cmp, generator line)
- A1. Canonical phrase at the unlock call site in the generator template (removes
  the 佐藤 search-replace need; see decision #2).
- A2. Decoy-string camo: generator emits per-instance N inert strings (N drawn from
  seed RNG) carrying RLO/PDF pairs and zw chars; whitelist = generator's own decoy
  blocks ONLY. Zero functional/printing strings touched.
- A3. Zero-width identifier option: post-obf micro-pass that renames a seeded subset
  of generated identifiers with ZWJ tails (or js-confuser zeroWidth generator when
  the jsc variant is used). Deterministic, validated by battery.
- A4. FEFF sprinkle micro-pass (post-obf, token-boundary inserts) — cosmetic only.
- B-phase memory & transport items below.

### Phase B — memory + telemetry hygiene (the "under-thought" gaps)
- B1. Transport audit: confirm every outbound call rides the app's own request layer
  (native headers/X-Super-Properties/UA/key order), payloads byte-shape identical to
  real client calls, cadence disciplines as documented. Produce
  `TRANSPORT_SHAPE.md` checklist (no fake presence, no new origins, fail-closed URL
  guard already in O8.3).
- B2. Retention scan: assert no decoded lexicon/phrase table outlives its call
  (code-anchor + runtime check).
- B3. Route table & residual plaintext sweep: extend band-rot coverage to any
  leftover readable strings the audit finds (S3 did codenames+phrases; check
  routes, URLs, labels).
- B4. OPTIONAL (user pick): move large static pools into a Uint8Array backing store
  behind the existing decode layer (shape change only; validation cost ~1 battery).
- B5. Explicitly non-goals (recorded): no active anti-CDP/anti-debugger,
  no timing-fingerprint countermeasures, no heartbeat/presence spoofing.

### Phase C — regenerate + validate (mirrors Shard-3 pipeline)
core -> generator (fresh seed, suite O.8.5-S4) -> lexenc -> shardify -> strip
(comment-free) -> battery: harness-default consumer + unlocked, L1/L0, unlock-unit
with canonical phrase, negative gate, duplicate-paste guard, stress
multi/midrun/srvdone/blip, MC readout, determinism byte-exact x2, residue scans
(zero old phrase, zero plaintext tells, zero comments).

### Phase D — last mile + packaging
- D1. Whole-file uniform obfuscation (obfuscate-final.js, seed-pinned) -> seam-free
  single-line product.
- D2. Optional second variant with js-confuser (heterogeneity evidence).
- D3. Release bundle (payload + 6 pieces + stitcher + README + SHA256SUMS), mirror
  O8.5-Shard-3.zip layout; plus optional compressed self-extract delivery
  (<~100 KB paste) if wanted.
- D4. Record + docs: O8.5-S4_RECORD.md, CURRENT_STATE.md update, CHEATSHEET
  appendix (phrase/digest/marker scheme), CHANGELOG.md row O.8.5-S4 (existing
  format), OBFUSCATION_TECHNIQUES.md additions (zw/RLO camo, memory-hygiene,
  transport-shape invariants, engine rotation).
