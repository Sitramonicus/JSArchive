## Hypothesis
The live O8.2-Juggle 404 (`GET https://discord.com/[object%20Object]`) is an object being
concatenated into a request URL during the applications lookup. Strings are not the cause:
all 23 Juggler fallback arrays decode to the correct plaintext with fp[0]=42 (22/22 verified).
The 404 therefore comes from a non-string quest `application`/id reaching the URL builder.

## Root-cause findings (evidence)
1. O8.2-Juggle keys: 22/22 decode to canonical strings (`webpackChunkdiscord_app`,
   `/quests/`, `getRunningGames`, …). Not a decoder problem.
2. URL arithmetic repro (Node):
   `"/applications/public?application_ids=" + { id: "9999" }` ⇒
   `…= [object Object]` ⇒ exactly the observed
   `https://discord.com/applications/public?application_ids=[object%20Object]` 404.
3. Older jugglers (O7.42-A/B/C, O7.45-D from the gist) failed differently: their shipped
   ciphertext arrays are corrupt — only 2–3 of 22 strings decode to the correct plaintext
   under ANY key (`_0xq0` → `wepackChunkdiscord_app` [missing "b"], `_0xm2` →
   `getGameFkrPqD`, `_0xm6` → `flushWqitQueue`). That reproduces the past transcripts exactly:
   - Attempt A: bad `_0xq0` → `window["wepack…"]` undefined → "module doorway is unavailable".
   - Attempt C/D: fixed `_0xq0`, bad method-name arrays → pockets all false (cache 8291).
   Fixing those requires regenerating the arrays with a correct encoder — NOT a runtime change.
