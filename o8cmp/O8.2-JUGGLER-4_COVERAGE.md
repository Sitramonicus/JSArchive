# O8.2-Juggler-4 — decoder logic + coverage logging (2026-09-06)

sha256 `9ed27d5a91b09336abfc08fcafabf5594081c41b1e11b43a3195440807199222`

## 1. Which mode made your O8.2-Juggler-3 live run "work"?

**The embedded (polymorphic) key fallback — not environment-derived keys.**

In J-3 (and J-4 as shipped) every constant is `_0xJuggle([0], [42, ...])`. The first guard in
the decoder is:

```js
if (!ep || ep.length <= 1 || ep[0] === 0) { /* embedded fallback only */ }
```

`ep = [0]` means **the env matrix is not armed** — it is compiled into the payload but never
executes. All 23 strings decode via `fp[0] = 42`. That is why it worked identically to plain
O8.2: same ciphertexts, same key, same result. It is deterministic, not "env-derived that
happened to agree".

J-4 now *proves* this on every run: the coverage line prints
`embeddedFallbackOnly: 23, envMatrixArmed: 0, envDecoded: 0`.

## 2. Decoder logic (as originally conceived vs. as built)

### Original idea (J-1 / O7.42 era)
- Ship each string encrypted under a key derived from the client environment: 5 sources × 4
  hashes = 20 combos. At runtime, try each combo; first decode passing a printable-sanity
  regex wins; if all fail → embedded fallback key.

### Why that design is dangerous (confirmed by testing)
1. The sanity regex is weak: XOR garbage over letter-ish ciphertext can itself be letter-shaped
   and pass. First-valid-wins can therefore return **garbage as an "env hit"** (my unit test
   reproduced this: a wrong key produced a valid-looking but wrong string).
2. If env arrays are mis-built (the O7.42 corruption class: 2–3/22 strings decodable under any
   key), the old decoder returned silent garbage or logged per-constant fallback spam —
   exactly the "tons of errors piling up" you saw.
3. Any real env mode must coexist with a fallback (canary), so an analyst can always force the
   fallback — that exposure is inherent to the dual-mode design, not a bug.

### O8.2-Juggler-4 decoder (cross-check design)
- **Mode B (shipped): `ep = [0]`** → embedded fallback only. Deterministic, zero env risk.
- **Mode A (armed, via builder): `ep = [key, ...bytes]`** → evaluate the full 20-combo matrix,
  but **credit env only when a combo's decode exactly equals the embedded fallback decode**
  (key agreement). A random garbage decode can never match, so env mode cannot return garbage;
  if the client changes and env keys stop agreeing, every string logs `env-miss` and falls back
  — the canary you originally wanted, without the crash cascade.
- **Fallback sanity check:** every embedded/fallback result is regex-checked. A corrupt array
  (O7.42 class) now raises one clear `[Juggler] … corrupted array?` warning instead of silently
  poisoning the run with `wepackChunkdiscord_app`-style strings.

## 3. What the new LOG_LEVEL = 2 logs look like

Per constant (23 lines):
```
[O7-DIAG] Juggler decode {name: '_0xq0', mode: 'embedded-fallback', key: 42, len: 23, valid: true}
[O7-DIAG] Juggler decode {name: '_0xq1', mode: 'env', source: 'DiscordNative.app.getVersion', hash: 'djb2-ish', key: 214, combosConsistent: 3, len: 13, valid: true}
[O7-DIAG] Juggler decode {name: '_0xm0', mode: 'env-miss->embedded-fallback', key: 42, envSourcesAvailable: 5, combosConsistent: 0, len: 34, valid: true}
```

One aggregate (after the 23rd constant):
```
[O7-DIAG] Juggler coverage {
  total: 23,
  embeddedFallbackOnly: 23,      // or 0 when armed
  envMatrixArmed: 0,             // >0 when ep arrays are armed
  envDecoded: 0,                 // >0 when env keys agree with embedded plaintexts
  envMissThenFallback: 0,        // >0 when armed but env keys no longer agree (client update)
  fallbackSanityWarnings: 0,     // >0 = corrupted array detected
  envSourcesUsed: 'none (env path not exercised)',  // e.g. {DiscordNative.app.getVersion: 23}
  envHashesUsed: 'none …',                            // e.g. {djb2-ish: 23}
  embeddedKeys: ['_0xq0', …],    // which constants used the embedded path
  envKeys: 'none'                // which constants used the env path
}
```

Interpretation guide:
- `envMatrixArmed: 0` → you are running the deterministic line (nothing env-derived happens).
- `envDecoded: 23, envMissThenFallback: 0` → genuine env coverage; env keys reproduce every
  constant. This is the "it really is environment-derived today" state.
- `envDecoded: 5, envMissThenFallback: 18` → partial agreement (e.g. some sources empty or a
  hash no longer matches); still safe, still works, but env coverage is partial.
- `envDecoded: 0, envMissThenFallback: 23` → client changed; every string fell back cleanly.
  No errors, no cascade — the canary did its job.
- `fallbackSanityWarnings: N` → stop: arrays are corrupt (rebuild with the builder).
