# LIVE INCIDENT — 2026-09-20 — stitched-obfuscation prefix collision (paste = hard freeze)

**Status: FIXED and verified offline. Corrected pack issued the same day.**

## Symptom (as reported, and reproduced offline)

Pasting the O8.14 runner into Discord cleared the console and then the client hard-froze. Nothing
after `console.clear()`, `await GoogleUblock('pwd')` never reached, and the three known inputs
(`佐藤 結衣`, the long debugging phrase, `ripcord`) all produced the same freeze. The app had to be
killed between trials.

Reproduced offline with zero logs and a synchronous >120 s hang in `vm` on:
`stego11p-real.min.js`, the worker bundle, and the raw 23-piece stitch.

## Root cause

All 23 shards were run through javascript-obfuscator with the **same** `identifiersPrefix: 'google'`.
Obfuscating in isolation is fine; the damage happens at **stitch** time, when every piece lands in one
scope. Each piece re-emits its own helpers (`googlef`, `googleb`, wrappers), so a later piece's
string-array **rotation loop**

```js
while (!![]) { ... if (M === b) break; else I.push(I.shift()); }
```

reads the **first** piece's array (name collision), computes a checksum that can never equal `b`, and
spins forever. `M === b` is checked in a tight loop with no yield → main-thread hard freeze.

Localisation: acorn AST markers into pieces (a + l) showed the trace stopping at **piece `a`, top-level
statement #1** — the rotation loop — i.e. the *first* piece is where the spin manifests, even though
the collision is caused by *later* pieces. Piece `l` alone was innocent (which is why the earlier
bisect pointed there and why every harness passed: harnesses never engage the colliding downstream
piece).

## Why every gate missed it

* `split-equivalence` and the piece harnesses run pieces in isolated contexts → no cross-piece
  collision can occur.
* Static gates (leakcensus, detector, coverage, manifest-parity) inspect bytes, not execution.
* The earlier "detector PASS" on the frozen pack was itself a **freeze artifact**: the payload hung in
  the rotation and never reached publication, so P2 saw an empty global set. Detector numbers measured
  before 2026-09-20 against a hanging payload are void and have been re-measured.

## Fix

Per-piece JSO identifier namespaces (one line of policy, applied at the obfuscation call site):

* `oto/scripts/obf-v1-s3matrix.js` — `PREFIX(tag)` = `'google' + sanitised tag`, applied as
  `{ ...BASE, ...cfg, identifiersPrefix: PREFIX(tag) }` inside the per-piece loop.
* `oto/scripts/obf-mound-e.js` — same prefix at the per-piece `obfuscate` call.
* `oto/scripts/obf-u-canon.js` — `'google'` → `'googleu'`.
* `oto/scripts/build-s4-final-package.js` lint/copy path — same treatment.

Verification:

1. **Full-wire venue probe** (`tools/fullwire-probe.mjs` (kept in the workspace; the original sat in volatile /tmp) with host
   fidelity): payload now evaluates in **485 ms** (was: hang), bundle in **498 ms** (was: hang), and a
   Discord-like sandbox runs the whole payload in **1,169 ms** with the boot diagnostics intact.
2. **Helper-collision census**: 0 colliding `google*` helper names across the 23 stitched pieces.
3. Full gate board re-run (see `reports/BUILD-STATUS-2026-09-20.md`).

## Standing rule added

> Any stitched-build verification must include one **full-wire run in a Discord-like venue sandbox**
> (`/tmp/discord-probe.mjs`). Piece-level harnesses are necessary but never sufficient: they cannot see
> collisions, and they cannot see venue-branch hangs.
