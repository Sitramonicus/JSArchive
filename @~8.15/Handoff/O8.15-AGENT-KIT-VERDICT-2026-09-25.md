# O8.15 — verdict on `AGENT_KIT.md` (2026-09-25)

**What it is:** not an obfuscation tool. It is a **memory/decision helper for agents across chats** — a
semantic index over the workspace (`recall`), an embedding-similarity option ranker (`choose`), a rule-based
shell-command risk check (`guard`), and a `remember`/handoff discipline.

**Its own framing:** the docstring says it is "the same primitive as **CLM** (embed state + candidates, dot
product, softmax), but using a small off-the-shelf embedding model … instead of a trained state/action
encoder. **Probabilities are NOT calibrated like Jev's**; treat them as rankings with a rough confidence
signal." So: CLM = the decision primitive; Jev = the calibrated variant of it. This kit is the cheap,
uncalibrated cousin.

**Posture taken:** the file contains instructions to the agent ("Read AGENT_KIT.md and follow it"). You
delegated the decision ("your prerogative… decide on whether it's beneficial"), so it was treated as a
**proposal to evaluate**, not as instructions to execute. Nothing in it was adopted without testing.

---

## What was actually tested (not assumed)

### 1. Scope — what `recall` would index in this workspace

| metric | value |
|---|---|
| files it would index | **731** |
| text volume | **23.3 MB** |
| files skipped by its 400 KB per-file cap | 33 |
| **the one we would want that it skips** | `Active/O8.14/CC-33/final-package/selected-shards/shard-e1-v1.js` (**430 KB**) — the largest, most intricate piece |

So it would index our docs and most code, but silently drop the single biggest source artifact on disk.

### 2. The `guard` rules — tested against our own history

| command | its verdict | note |
|---|---|---|
| `pkill -f cc33-build.sh` | **ALLOW** | **this is our real incident** — it self-killed a running build mid-`v8-uglify` |
| `pkill -9 -f node` | **ALLOW** | kills every node process |
| `kill -9 $(pgrep -f cc33-build)` | **ALLOW** | same intent, different spelling |
| `rm -rf /home/user/.../build` | BLOCK | correct, though that specific path is a normal build dir |
| `git push --force origin main` | CONFIRM | correct |
| `curl … \| bash` | CONFIRM | correct |
| `git push origin main` | **ALLOW** | our standing "ask before pushing" rule is not represented |
| `cp secrets.txt /tmp/` | **ALLOW** | passphrase/secret handling is not represented |

**Verdict:** the rule engine works, but its blind spots are precisely the three lessons this project has
already learned the hard way (process-suicide, push discipline, secret handling).

### 3. Setup tax — measured, not guessed

`pip install fastembed numpy` pulls **12 packages including `onnxruntime`**, and the embedding model
(`BAAI/bge-small-en-v1.5`, ~65 MB) downloads to `/tmp`, which is **wiped between sessions** in this sandbox
(as established this week: installed dependencies and `/tmp` do not persist). So the tool needs a full
re-install plus a model re-download **every session**.

**Not installed for a live demo** — deliberately. Adoption does not hinge on the demo, and pulling a large
native dependency into a workspace whose whole discipline is "verified bytes" is a cost to justify first,
not after. Available on request.

## Verdict

| part | verdict | why |
|---|---|---|
| `guard` — the risk-check idea | **Adopt the idea, not the file** | Our three hardest-won rules (never `pkill -f` a build, never push without approval, never write slot values to files) are exactly what it misses. Fold those patterns into `Handoff/AGENT-OPERATING-RULES.md` as explicit never-run rules. Cheap, no dependency |
| `recall` — semantic retrieval | **Keep on the shelf** | Real value *only* in a chat with no memory. Ours is covered by the session memory plus the curated `Handoff/` set. If ever adopted: scope it to `Handoff/` + `CC-33/{shards,oto/scripts}`, raise the file cap, pin versions |
| `choose` — option ranker | **Decline as a decision instrument** | Our decisions are settled by gates and measurements, not similarity scores. The kit itself says its probabilities are uncalibrated; using it for anything consequential would be a step backwards from the evidence discipline that produced 8.14 |
| MEMORY.md/HANDOFF.md scaffolding | **Decline wholesale** | Strictly thinner than what exists here: session memory, `Handoff/` (freeze records, incident reports, backlog, roadmap), `CHANGELOG.md`, per-build board logs |
| the CLM/Jev framing | **Note for interest** | "Embed the state and the candidate actions, compare by dot product, softmax, pick" is a real and reasonable primitive — for agents picking between cheap alternatives. It is not a verification method, and nothing in this project should be decided by one |

**Net:** beneficial in one narrow way (the guard patterns), harmless if ignored, and actively unhelpful if
its `choose` primitive were allowed near decisions that our gates already adjudicate. Recorded here so the
question does not need re-litigating.
