# O8.14 — r3 baseline restore (2026-09-20, "bring back the baseline")

**Order.** The operator's directive: *"8.14 deliberately dropped it without notice!? Bring back the
baseline. It's been properly functional throughout the older versions…"* — i.e. restore the r3 running
game/quest dispatch behaviour exactly where 8.14 changed it. The 4-point bounded-signal plan and the
"which quest type" question were **not** approved; restoration is the course.

## 1. What actually differed (diagnosis, unchanged from the fourth refresh)

| | O8.13-r3 (`Active/O8.13/shards/shard-e.js`) | O8.14 before this pass |
|---|---|---|
| dispatch binding | `_0xsend = _0x8.dispatch.bind(_0x8)` (:641) | `_0xsend = _0xr2.v814….dispatcher(S._0x8)` (e2:103) |
| start | `_0xsend({type: _0xe0, removed: running, added: [_0x21], games: [_0x23]})` (:851) | exclusive `_0xprimaryActivity.begin()`; `removed: []` |
| exclusivity | **none** — every task dispatched its own record | one `active` slot; `begin` spins ≤5000 on `GoogleDelay(1)`; busy → returns false |
| busy behaviour | n/a | worker threw `"activity-busy"` → **chore abandoned** |
| cleanup | `_0xsend({removed: [_0x21], added: [], games: []})` (:858) via `removeSelf = _0xe8a7(cleanup)` | `_0xprimaryActivity.end()` → `removed: [record]` |

The earlier "8.14 dropped the running-game dispatch" claim was wrong and is corrected: `_0xe0` decoded is
`RUNNING_GAMES_CHANGE` and 8.14 still sent it — the change was **exclusivity plus `removed: []`**, and
the functional cost was that any chore that did not win the slot never progressed. The enrolment filter
was ruled out first: keys are byte-identical to r3 (`shard-e.js:232-234` vs `shard-e1.js:235-237`), same
seek taxonomy.

## 2. What was changed

* `shards/shard-e2.js` — the activity bridge exposes `dispatch(record, priorRunning)` (emits
  `{type: _0xe0, removed: priorRunning or [], added: [record], games: [record]}`) and
  `retract(record)` (emits `{removed: [record], added: [], games: []}`). Both wrapped so a broken
  dispatcher cannot take an error path down. The exclusive `begin`/`end` path is untouched.
* `shards/shard-e3.js` — when `_0xprimaryActivity.begin()` reports the slot busy, the worker now calls
  `_0xprimaryActivity.dispatch(_0x21, running)` and carries on (`_0xfallback` flag) instead of throwing
  `"activity-busy"`; cleanup calls `retract` when it took that path. `running` is the same accessor r3
  used (`S._0x4?.[_0xm1]?.()`), declared at e3:76 in the same worker scope.
* No other behaviour was re-gated, dwinelled or trimmed. `rgf` stays off for `e3`; opaque prefixes,
  timestamps and `[Google <channel>]` labels are unchanged.

**Note for future edits:** `shards/*.js` are re-authored from `*.orig` by `rebind-registry-keys.mjs`
every build — but only `shard-a/c/e/h` have `.orig` files. `shard-e2/e3/e4` do **not**, so editing them
in place is correct (and the edits were confirmed present in the `v4-closure` / `v5-terser` / `mound-e`
intermediates before the stitch).

## 3. Defects found and fixed while shipping the restore

1. **Error-path shim under-covered (three defects).** (a) ASCII-only name filter
   (`/^[A-Za-z_$][\w$]*$/`) vs mixed-script mangled names — five names dangled in `shard-e1-v1`,
   only `Lattice274` qualified; (b) the shim read the lint's `--json` summary, whose per-name
   `inCatch` flag does not match the per-site verdict the gate uses; (c) its prelude went into the
   raw-stitch scratch file that later passes never re-read (proof: `Lattice274` "declared" by 2b was
   still dangling in the finished bundle). Fixed by a new **2c pass** that re-scans the *finished*
   artifact with the gate's own `--catch-only` text detector.
2. **Placement.** The shipped bytes must still **end** with `lexSetPins([...])` — the stego builder
   re-pins off a `$`-anchored tail regex and aborts with *"G8 repin: raw tail not found"*. The first
   2c attempt appended after it and broke the embed.
3. **`let`, not `var`.** Appended `var` declarations made terser emit a var-list ending in a comma,
   which the builder's anti-grep noise (joined onto the tail with a leading comma, because it assumes
   the last statement is an expression) turned into `…,Lattice274=function(){},"(()=>{[…` — a payload
   that **threw before logging anything** ("Unexpected token '('"). Prepending fixed the shape; then
   detector-replay P2 flagged that top-level `var` **publishes globals**, so the shim declares with
   **`let`** (declarative binding, invisible on `globalThis`).
4. **Build harness.** The piece-scope lint's diagnostic `|| { node … | grep … | head }` group ended on
   `grep`; a no-match exits 1, which under `set -e` **aborted the cascade before the stego stage** —
   the first roll produced no new payload at all. Guarded with `|| true`; a malformed duplicate echo
   removed. Lesson recorded: check artifact **mtimes**, and never take an exit code from a piped
   command as the build's result (`bash … | grep` reports grep's status).
