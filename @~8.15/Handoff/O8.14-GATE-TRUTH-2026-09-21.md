## 3. Why the live trace showed `GoogleUblock('ripcord') → false`

`shard-u.js:9` is the whole answer:

```js
function _0xcheckMain(input){ if(Date.now()-_0xt0>60000 && !(_0xdbgOK||_0xrcdOK)) return false; … }
```

`_0xt0` is stamped when the payload evaluates, so **the FNV path — the only path that accepts
`pwdRcd` — closes 60 seconds after load.** The operator's two calls came at the end of a session
(the line immediately after them carried `+187.3s`), i.e. well past 60 s.

`pwdDbg` still returned `true` in the same trace because it *also* sits on the SHA-256 `polyP` path,
which has no time window. But the flag-setting call that follows it (`_0xrcdGate.check(pw)`) is the
same windowed function, so **`_0xdbgOK` never gets set after 60 s either** — the level stays 0 and
the diagnostic sink never opens.

## 5. What this means for the acceptance line

> *"tag visible at level ≥1 with either approved passphrase"*

- `Log.say` / `info` / `warn` tags: **met** at any time (unconditional).
- `Log.diag` + everything routed through `Log.queue`/`flush` (`[Google diag] …`): **met only inside
  the 60-second window.** Outside it, no passphrase — including correct ones — re-opens the sink.
- `pwdRes` / `pwdAK` / `pwdView`: **only usable inside the 60-second window** (they require a prior
  level ≥ 1 in the same session, which only the windowed path can produce).
